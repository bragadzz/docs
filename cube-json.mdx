O `cube.json` fica na **raiz do .zip** e diz à Cube como rodar o seu projeto. Ele é opcional no painel (que detecta sozinho e mostra para você conferir), mas deixa o envio pela API automático.

```json cube.json
{
  "name": "Bot da loja",
  "language": "node",
  "version": "22",
  "command": "node index.js"
}
```

## Chaves

<ResponseField name="language" type='"node" | "python" | "java" | "go" | "php" | "ruby" | "dotnet" | "elixir" | "static"' required>
  A linguagem do projeto. `java` roda um `.jar` pronto ([Hospedar Java](/hosting/java)), `go` compila o projeto a cada envio ([Hospedar Go](/hosting/go)), `php` instala o `composer.json` e serve o site sem comando ([Hospedar PHP](/hosting/php)) `ruby` instala o `Gemfile` ([Hospedar Ruby](/hosting/ruby)), `dotnet` publica o projeto C#, F# ou Visual Basic a cada envio ([Hospedar .NET](/hosting/dotnet)) e `elixir` baixa e compila o projeto do `mix.exs` a cada envio ([Hospedar Elixir](/hosting/elixir)). `static` é o **site só de HTML**: a Cube serve os arquivos, sem comando, versão nem build. Veja [Hospedar um site HTML](/hosting/static-site).
</ResponseField>

<ResponseField name="command" type="string">
  Obrigatório em `node`, `python`, `java`, `ruby`, `dotnet` e no bot `php` (o `static` não tem; no `go`, no `elixir` e no site `php` é opcional). O comando que inicia o projeto, como `node index.js`, `tsx src/index.ts`, `npm start`, `python main.py`, `java -jar bot.jar`, `php bot.php`, `ruby bot.rb`, `dotnet /dados/publish/Bot.dll` ou `mix run --no-halt`. De 1 a 500 caracteres, numa linha só. Ele roda dentro da pasta do projeto. No `go`, sem ele roda o programa que o build gera, `/dados/bin/app` (com ele, passe opções: `/dados/bin/app -config prod.yml`). No `elixir`, sem ele roda `mix run --no-halt`, que sobe o projeto do `mix.exs`. No site `php`, sem ele a Cube serve o site (veja `root`). No `dotnet`, o comando roda o `.dll` que o build publica, com o nome do projeto: `dotnet /dados/publish/<projeto>.dll`; um `.dll` pronto roda como veio, sem build (`dotnet app.dll`).

  Quando o comando é só `node <arquivo>`, `tsx <arquivo>`, `python <arquivo>`, `java -jar <arquivo>`, `php <arquivo>`, `ruby <arquivo>` ou `mix run --no-halt <arquivo>.exs`, esse arquivo vira o **arquivo principal** do projeto (`entry` na API). Depois, em **Configurações** › **Geral**, o comando de início é opcional: vazio, roda o arquivo principal (o `.ts`, `.mts` ou `.cts` com o `tsx`, o [TypeScript direto](/hosting/discord-bots)).

  Bun e Deno rodam pelo npm, com `npx bun index.ts` ou `npx deno run -A main.ts`. Veja [Bun e Deno](/hosting/bun-and-deno).
</ResponseField>

<ResponseField name="name" type="string">
  O nome que aparece no painel, de 1 a 40 caracteres. Sem ele, vale o nome do arquivo `.zip`.
</ResponseField>

<ResponseField name="type" type='"bot" | "site"' default="bot">
  `bot` é um processo sem endereço na internet (bots de Discord, workers, tarefas). `site` é um site ou API que recebe visitas por HTTPS. Veja [Sites e APIs](/hosting/sites-and-apis). Com `"language": "static"`, o padrão é `site` (e `bot` é recusado); no `php` sem `command`, também `site`.
</ResponseField>

<ResponseField name="version" type="string">
  A versão da linguagem. Node.js: `"20"`, `"22"`, `"24"` ou `"26"`. Python: `"3.11"`, `"3.12"`, `"3.13"` ou `"3.14"`. Java: `"21"` ou `"25"`. Go: `"1.26"` ou `"1.27"`. PHP: `"8.4"` ou `"8.5"`. Ruby: `"3.4"` ou `"4.0"`. .NET: `"10"`. Elixir: `"1.20"`. Sem ela, vale o Node.js **24** (a LTS), o Python **3.12**, o Java **21**, o Go **1.27**, o PHP **8.4**, o Ruby **3.4**, o .NET **10** ou o Elixir **1.20**. O Node.js 20 ainda sobe, mas está fora de suporte desde 30/04/2026: não recebe mais correções de segurança.
</ResponseField>

<ResponseField name="memoryMb" type="integer">
  A memória do projeto, em MB. O mínimo depende do plano: bot **256** nos planos pagos e **100** no Free; site **512** em todo plano. Um projeto **Java** pede pelo menos **256** em qualquer plano, então não cabe no Free (`language_not_in_plan`). Sem a chave, vale o mínimo do seu plano; no Java, **512 MB** (ou o que sobra no plano, nunca menos de 256). Abaixo do mínimo, o envio é recusado com `invalid_config` (com `field: "memoryMb"` e o `minMemoryMb` do plano). A soma da memória de todos os seus projetos não pode passar a do plano: no Free, a conta tem **100 MB** no total, e um bot que pede mais é recusado com `insufficient_memory`. Veja [Planos e memória](/account/plans).
</ResponseField>

<ResponseField name="port" type="integer" default="8080">
  Só para `site`: a porta em que o seu app escuta, de 1024 a 65535. O app recebe o mesmo número na variável `PORT`.
</ResponseField>

<ResponseField name="subdomain" type="string">
  Só para `site`: o nome em `nome.cubehost.dev`. De 3 a 32 caracteres, com letras minúsculas, números e hífen. Sem ele, a Cube gera um a partir do nome do projeto. Veja [Endereço e domínios](/hosting/domains).
</ResponseField>

<ResponseField name="build" type="string">
  Um comando que roda depois de instalar as dependências, como `npm run build`. Sem a chave, o build é automático: se o `package.json` tem um script `build`, ele roda, no `go` a Cube compila a pasta do arquivo principal a cada envio, no `dotnet` publica o projeto (`dotnet publish`) e no `elixir` roda o `mix compile`. Use `""` para não rodar nenhum build. O `static` não tem build, e o `java` não compila nada (o `.jar` já vem pronto). No `php` e no `ruby`, o build roda depois do `composer install` ou do `bundle install` (no Rails, o `assets:precompile`). No `elixir`, o build roda no lugar do `mix compile`, depois do `mix deps.get` (no Phoenix com assets, `mix do compile + assets.deploy`); no `dotnet`, no lugar do `dotnet publish`, e o `command` roda o `.dll` que ele gera (o site serve a pasta desse `.dll`).
</ResponseField>

<ResponseField name="root" type="string" default="a pasta do index.html">
  No site `php` sem `command`: a pasta que a Cube serve, como `"public"` ou `"web"`; sem ela, a `public` quando existe, senão a raiz. O `.env`, o que começa com ponto, o `cube.json`, os `composer.*` e a pasta `vendor` nunca são servidos ([Hospedar PHP](/hosting/php)).

  No `static`: a pasta servida, a partir da raiz do .zip, como `"dist"` ou `"site/public"`; `""` é a raiz. Sem ela, a pasta do `index.html` mais raso do .zip: a raiz quando ele está lá, ou `dist` quando só existe `dist/index.html`. Precisa ser uma pasta dentro do projeto, sem `..` e sem pasta que começa com ponto; fora disso, `invalid_config` com `field: "root"`.
</ResponseField>

<ResponseField name="systemPackages" type="string[]" default="[]">
  Programas do sistema que o projeto usa, de uma lista fechada, como `["poppler-utils"]` para ler PDF. Veja [Pacotes do sistema](#pacotes-do-sistema). Nome fora da lista é recusado com `unsupported_system_package`, e o `static` não tem pacotes.
</ResponseField>

<Warning>
  Chave desconhecida é recusada com o erro `invalid_config`, dizendo qual chave. Assim um erro de digitação não passa calado. `port` e `subdomain` num `bot` também são recusados, e também `command`, `version` e `build` no `static` e `root` fora do `static` e do site `php` sem `command`.
</Warning>

## Pacotes do sistema

Alguns projetos precisam de um programa do sistema, além das dependências do `package.json` ou do `requirements.txt`: ler PDF, converter imagem, reconhecer texto, compilar uma dependência nativa. Peça em `systemPackages`, com nomes desta lista:

| Pacote | O que traz |
| --- | --- |
| `build-essential` | Compilador C e C++ (`gcc`, `g++`, `make`), para dependências que compilam ao instalar. No Node.js, junte o `python3` (o `node-gyp` precisa dele). |
| `curl` | Baixar arquivos e chamar endereços pela linha de comando. |
| `fonts-dejavu-core` | Fontes DejaVu, para texto em imagens e PDFs. |
| `fonts-liberation` | Fontes com as medidas de Arial, Times New Roman e Courier New. |
| `fonts-noto-cjk` | Fontes para chinês, japonês e coreano. |
| `fonts-noto-color-emoji` | Emojis coloridos em imagens e PDFs. |
| `ghostscript` | PostScript e PDF pela linha de comando (`gs`). |
| `git` | Git, para dependências que vêm de um repositório. |
| `graphviz` | Gráficos e diagramas a partir de texto (`dot`). |
| `imagemagick` | Converter e editar imagens (`convert`). |
| `libvips-tools` | A libvips, processamento rápido de imagens (`vips`), para bibliotecas que usam a do sistema. |
| `poppler-utils` | Ferramentas de PDF: o texto (`pdftotext`) e as páginas em imagem (`pdftoppm`). |
| `python3` | Python do sistema, que o `node-gyp` usa para compilar módulos nativos do Node.js. |
| `sqlite3` | Linha de comando do SQLite (`sqlite3`). |
| `tesseract-ocr` | Reconhecer texto em imagens (OCR, `tesseract`), com o inglês. |
| `tesseract-ocr-por` | Português para o reconhecimento de texto (`tesseract -l por`). |
| `unzip` | Descompactar arquivos `.zip`. |
| `zip` | Compactar arquivos em `.zip`. |

```json cube.json
{
  "language": "python",
  "command": "python main.py",
  "systemPackages": ["poppler-utils", "tesseract-ocr", "tesseract-ocr-por"]
}
```

- **Todas as linguagens** com runtime (Node.js, Python, Java, Go, PHP, Ruby, .NET e Elixir) aceitam; o site estático (`static`) não tem. O `ffmpeg` já vem em todas, sem pedir.
- **Onde:** no `cube.json` do primeiro envio ou em **Configurações** › **Geral** › **Pacotes do sistema** no painel. Mudou depois? Vale no próximo início (o painel pede para reiniciar).
- **Quanto demora:** a primeira vez com uma combinação nova de linguagem, versão e pacotes, o projeto fica em **Instalando** de alguns segundos a uns 2 minutos (o `poppler-utils` leva uns 10 s; o `build-essential`, uns 45 s); depois, a mesma combinação sobe na hora, para qualquer projeto.
- **Na instalação também:** o `npm install`, o `pip install`, o `composer install` e o `bundle install` já rodam com os pacotes, então o `build-essential` (com o `python3`, no Node.js) resolve a dependência nativa que não tem binário pronto, e o `git` a que vem de um repositório.
- **Fora da lista** não entra: o envio é recusado com [`unsupported_system_package`](/errors#param-unsupported-system-package), e a mensagem traz a lista. Precisa de outro? Peça no [Discord](https://discord.gg/pv6D9tUsDV).

<Tip>
  No código, chame o programa como no seu computador: `execFileSync('pdftotext', ['arquivo.pdf', '-'])` no Node.js ou `subprocess.run(['pdftotext', 'arquivo.pdf', '-'])` no Python.
</Tip>

## Onde o cube.json vale

- **No painel:** ele preenche a tela **Configure o projeto**. O que você confirma na tela é o que fica valendo.
- **Na API:** se o formulário do [envio](/api-reference/projects/create) trouxer `language` e `command` (ou `language` e `entry`, e o comando sai do arquivo principal; ou só `language`, no `static`, no `go`, no `elixir` e no `php`), o formulário vale e o `cube.json` é ignorado, menos o `systemPackages`: ele vale mesmo assim, a não ser que o formulário traga o campo `systemPackages`. Sem eles, vale o `cube.json`. Sem nenhum dos dois, a raiz do .zip decide quando não há dúvida: só HTML (o `index.html` na raiz e nenhum `package.json`, `requirements.txt`, `pyproject.toml`, `go.mod`, `composer.json`, `Gemfile`, `mix.exs` nem projeto do .NET) vira [site estático](/hosting/static-site); o `go.mod` sem outro manifesto vira [Go](/hosting/go); um único projeto do .NET na raiz (`.csproj`, `.fsproj` ou `.vbproj`) vira [.NET](/hosting/dotnet) com ele de arquivo principal (com só a solução `.sln`, a mensagem diz .NET e pede o comando); o `mix.exs` vira [Elixir](/hosting/elixir), com o `mix run --no-halt`; o `composer.json` sem outro manifesto vira um [site PHP](/hosting/php) (o `package.json` junto dele, do `Gemfile`, do projeto do .NET ou do `mix.exs` é o dos assets, como o Vite do Laravel, e não conta); um único `.jar` na raiz, sem manifesto nenhum, vira [Java](/hosting/java) com ele de arquivo principal. Qualquer outro é recusado com `missing_config` (com um manifesto de uma linguagem só, como o `Gemfile`, a mensagem diz a linguagem e pede o comando).
- **Pasta dentro do .zip:** se o `.zip` tiver uma única pasta no topo e nenhum `cube.json` na raiz, essa pasta vira a raiz. Isso cobre o "Compactar" do Windows e do macOS.

## Vindo de outra hospedagem

Sem `cube.json`, a Cube lê o arquivo de configuração de outra hospedagem que estiver na raiz do .zip e traduz para as chaves do `cube.json`. Assim o projeto sobe sem você reescrever nada. Vale no painel (a tela **Configure o projeto** diz de qual arquivo a configuração veio), na [API](/api-reference/projects/create) e na [CLI](/cli) (0.2.5 ou mais nova).

Os arquivos lidos, nesta ordem: `squarecloud.app`, `squarecloud.config`, `discloud.config` e `.shardcloud`. O formato é `CHAVE=valor`, uma por linha, com `#` para comentário.

| No `cube.json` | `squarecloud.app` / `.config` | `discloud.config` | `.shardcloud` |
| --- | --- | --- | --- |
| `language` | `RUNTIME`, senão a extensão do `MAIN` | a extensão do `MAIN` | `LANGUAGE`, senão a extensão do `MAIN` |
| `command` | `START`, senão o que roda o `MAIN` | `START`, senão o que roda o `MAIN` | `CUSTOM_COMMAND`, senão o que roda o `MAIN` |
| `type` | `site` quando tem `SUBDOMAIN` | `TYPE` | `site` quando tem `SUBDOMAIN` |
| `subdomain` | `SUBDOMAIN` | `ID` (só no site) | `SUBDOMAIN` |
| `memoryMb` | `MEMORY` | `RAM` | `MEMORY` |
| `version` | `VERSION` | `VERSION` | `VERSION` |
| `name` | `DISPLAY_NAME` | `NAME` | `DISPLAY_NAME` |
| `build` | — | `BUILD` | — |

- O `MAIN` em `.js`, `.mjs`, `.cjs`, `.ts`, `.mts` ou `.cts` é Node.js (o `.ts` roda com o `tsx`), em `.py` é Python, em `.jar` é Java (`java -jar`), em `.go` é Go (a pasta dele é a que o build compila), em `.php` é PHP, em `.rb` é Ruby, em `.csproj`, `.fsproj`, `.vbproj`, `.sln`, `.dll` ou `.cs` é .NET, em `.ex` ou `.exs` é Elixir e em `.html` é o [site estático](/hosting/static-site), com a pasta do `MAIN` como `root`. O `MAIN=app.dll` da Square Cloud, com o projeto ou a solução na raiz, roda o publicado, `dotnet /dados/publish/app.dll`, e o build publica o projeto da raiz; sem eles, é um `.dll` pronto, que roda como veio (`dotnet app.dll`, sem build); o Elixir sem `MAIN` roda `mix run --no-halt`. O site PHP sem `START` é servido pela Cube, com a pasta do `MAIN` (`public/index.php` → `public`); o bot PHP roda `php <MAIN>`. `RUNTIME`/`LANGUAGE` `golang` também vira `go`, e `csharp` e `c#` viram `dotnet`.
- `VERSION` com número vale quando a Cube tem essa versão (`22.11.0` vira `"22"`, `3.14.7` vira `"3.14"`, `1.27.1` vira `"1.27"`, `21.0.4` vira `"21"`, `8.5.10` vira `"8.5"`, `4.0.7` vira `"4.0"`, `10.0.12` vira `"10"`, `1.20.4` vira `"1.20"`); `recommended`, `latest` ou uma versão que não existe aqui deixam a padrão.
- A memória de lá é sugestão: abaixo do mínimo daqui, sobe ao mínimo do seu plano; acima do que sobra no plano, desce ao que sobra (o `MEMORY=256` entra com 100 MB no Free). Um subdomínio que não vale ou já está em uso aqui dá lugar a um gerado. O resto (`AUTORESTART`, `DESCRIPTION`, `AVATAR`, `APT`) é ignorado.
- Linguagem que a Cube ainda não tem (Rust…) é recusada com `unsupported_language`.
- O site precisa ouvir na porta da variável `PORT` (8080 por padrão), nunca numa porta fixa como a 80.

<Tip>
  Com um `cube.json` no .zip, ele vale e o arquivo da outra hospedagem é ignorado.
</Tip>

<Info>
  A configuração fica guardada no projeto depois do primeiro envio. Um `cube.json` diferente num **novo .zip** do mesmo projeto é ignorado. Para mudar nome, linguagem, arquivo principal, comando, versão, pasta servida, memória, subdomínio ou pacotes do sistema, use **Configurações** no projeto. Tipo e porta não mudam: para isso, crie um projeto novo.
</Info>
