Um projeto do tipo `site` recebe visitas pela internet. Ele ganha um endereço `https://nome.cubehost.dev`, com HTTPS automático desde o primeiro deploy.

<Note>
  Sites e APIs são dos planos pagos, a partir do **Block**. O mínimo de memória de um site é **512 MB**. Veja os [planos](/account/plans).
</Note>

<Tip>
  Site só de HTML, CSS e imagens, sem servidor? Não precisa de nada disto: veja [Hospedar um site HTML](/hosting/static-site).
</Tip>

## A regra de ouro: `0.0.0.0` e `PORT`

O seu app precisa escutar em **`0.0.0.0`** (não em `localhost` nem `127.0.0.1`), na porta da variável de ambiente **`PORT`**. A porta vem do `port` do `cube.json` (padrão `8080`). No **Novo projeto**, ligue a **Publicação na web** (ela já vem ligada quando o `.zip` parece um site) e escolha só o subdomínio: a porta não é pedida. Se o app ouve numa porta fixa, troque em **Configurações** › **Rede**, e ela vale no próximo início.

Se o app escutar em outro endereço ou porta, o visitante vê a página **Este site não respondeu**. Veja como corrigir em [Site não abre](/troubleshooting/sites#este-site-não-respondeu).

## Exemplos

<Tabs>
  <Tab title="Express">
    <CodeGroup>
    ```js server.js
    const express = require('express');

    const app = express();
    app.get('/', (req, res) => res.send('Olá da Cube!'));

    const port = Number(process.env.PORT) || 8080;
    app.listen(port, '0.0.0.0', () => console.log(`No ar na porta ${port}`));
    ```

    ```json package.json
    {
      "name": "minha-api",
      "main": "server.js",
      "dependencies": {
        "express": "^4.21.0"
      }
    }
    ```

    ```json cube.json
    {
      "name": "Minha API",
      "type": "site",
      "language": "node",
      "command": "node server.js",
      "memoryMb": 512,
      "subdomain": "minha-api"
    }
    ```
    </CodeGroup>
  </Tab>
  <Tab title="Flask">
    Use o `gunicorn` para servir o app. Ele precisa estar no `requirements.txt`.

    <CodeGroup>
    ```python app.py
    from flask import Flask

    app = Flask(__name__)


    @app.get("/")
    def inicio():
        return "Olá da Cube!"
    ```

    ```text requirements.txt
    flask==3.0.3
    gunicorn==23.0.0
    ```

    ```json cube.json
    {
      "name": "Minha API",
      "type": "site",
      "language": "python",
      "command": "gunicorn -w 2 -b 0.0.0.0:$PORT app:app",
      "memoryMb": 512
    }
    ```
    </CodeGroup>
  </Tab>
  <Tab title="Next.js">
    O build roda sozinho, porque o `package.json` do Next.js tem o script `build`. O comando de início passa o endereço e a porta. Envie o código-fonte, sem `node_modules` e sem `.next` (se ela vier, sai do envio); o Next exportado como site estático (`output: 'export'`) roda sem rotas de API nem páginas com servidor. Veja [Envie o código-fonte, não o compilado](/hosting/source-code).

    O cache do build (`.next/cache`) fica guardado entre os envios: o `next build` reaproveita o que já compilou, e os envios seguintes saem mais rápido.

    <CodeGroup>
    ```json package.json
    {
      "name": "meu-site",
      "scripts": {
        "dev": "next dev",
        "build": "next build",
        "start": "next start"
      },
      "dependencies": {
        "next": "^15.0.0",
        "react": "^19.0.0",
        "react-dom": "^19.0.0"
      }
    }
    ```

    ```json cube.json
    {
      "name": "Meu site",
      "type": "site",
      "language": "node",
      "command": "npx next start -H 0.0.0.0 -p $PORT",
      "memoryMb": 1024
    }
    ```
    </CodeGroup>

    <Warning>
      As variáveis de ambiente chegam ao app quando ele inicia, **não durante o build**. Variáveis que o Next.js embute no build (as `NEXT_PUBLIC_…`) ficam vazias. Por enquanto, coloque esses valores públicos num arquivo do projeto, como `.env.production` (nunca um segredo).
    </Warning>
  </Tab>
</Tabs>

## Enviar uma versão nova sem tirar do ar

Num site que está no ar, a versão de agora continua atendendo enquanto a nova instala: num `.zip` novo, no **Aplicar mudanças**, no **Voltar para esta versão** e no push do [GitHub](/github). A versão nova sobe ao lado, e as visitas só passam para ela quando ela responde na porta. Quem visita não vê o site cair.

| Fica no ar o tempo todo | Ainda sai do ar durante o build |
| --- | --- |
| Site estático, Python, Ruby, Go, Rust, .NET e Java, também com dependências novas | Next.js, Nuxt e todo Node.js com o script `build` |
| Node.js sem o script `build` e com as mesmas dependências | Node.js com dependências novas (o `node_modules` é instalado de novo) |
| PHP com as mesmas dependências | PHP com dependências novas (o `vendor/` é instalado de novo) |
| | Elixir |
| | Um comando de instalação ou de build próprio no [`cube.json`](/cube-json) |
| | **Reinstalar dependências** |

Quando o site sai do ar, ele fica fora o tempo do build mais a subida, como antes, e o log da instalação diz por quê.

- **Bot nunca:** o bot para antes do build, como sempre, porque dois bots com o mesmo token brigam no Discord. Um site que também conecta um bot roda duas vezes por alguns segundos na troca.
- **60 segundos para responder:** se a versão nova não responder na porta em até 60 segundos, ela sai, a anterior continua no ar e o envio falha com [`new_version_not_responding`](/errors#param-new-version-not-responding). O log da instalação diz o motivo e traz as últimas linhas do log da versão nova. Veja [Este site não respondeu](/troubleshooting/sites#este-site-não-respondeu).
- **O código novo fica no projeto:** mesmo quando a versão nova não respondeu, os arquivos dela já estão lá, e o próximo início (também o reinício automático depois de uma queda) roda ela. Corrija e envie de novo.
- **Memória:** por alguns segundos, as duas versões rodam juntas, dentro da memória do seu plano. Sem memória livre para as duas, o site reinicia como antes, e o log da instalação avisa.
- **WebSocket:** as conexões abertas na versão antiga caem e reconectam na nova.
- **Build com erro:** se a instalação ou o build falhar, o site para e fica com o erro, como antes.

## Páginas que o visitante pode ver

| O visitante vê | Quando | O que fazer |
| --- | --- | --- |
| **Este site está parado** (503) | O projeto não está no ar | Inicie o projeto no painel |
| **Este site não respondeu** (503) | O app não escuta em `0.0.0.0` na porta `PORT`, ou ainda está subindo | Confira o endereço e a porta no código e os logs |
| **Este endereço não existe** (404) | Nenhum site usa esse subdomínio | Confira o endereço em **Configurações** › **Rede** |
| **Este site está sobrecarregado** (503) | Conexões demais ao mesmo tempo no site | Espere alguns segundos; se for sempre assim, fale com a gente |

<Tip>
  Uma conexão que fica 100 segundos sem trocar nenhum byte é encerrada. Em WebSocket, mande um ping de tempos em tempos.
</Tip>

## Endereço

O subdomínio vem do `cube.json`, do painel ou é gerado a partir do nome. Troque quando quiser em **Configurações** › **Rede**. Veja as regras em [Endereço e domínios](/hosting/domains).
