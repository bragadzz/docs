### O que fica protegido

- `node_modules` e `__pycache__` aparecem **só para leitura**: eles são criados pela instalação. Para mudar uma dependência, edite o `package.json` ou o `requirements.txt` e use **Aplicar mudanças**.
- O ambiente do Python (`venv`) não aparece.
- Atalhos (links simbólicos) aparecem na lista, mas não são abertos nem seguidos.
- Arquivos que não são texto (imagens, `.zip`) não abrem no editor: baixe para abrir no computador.

## Arrastar arquivos e pastas do computador

Não precisa compactar nada: arraste arquivos e pastas do seu computador para a lista da aba **Arquivos**, ou use **Enviar** › **Enviar arquivos** ou **Enviar pasta**. Soltos na lista, eles vão para a pasta aberta; soltos em cima de uma pasta da lista, vão para dentro dela, com as subpastas.

Funciona como um commit: antes de gravar, o painel compara o que chegou com o que já está no projeto (pelo conteúdo de cada arquivo, calculado no seu navegador) e mostra, no **Enviar mudanças**:

- os arquivos **alterados** e os **novos**, que são enviados;
- os **iguais**, que não são enviados de novo;
- os **bloqueados**, com o motivo (uma pasta com o mesmo nome no projeto, um atalho no caminho, a pasta das dependências), que ficam de fora.

Clique em **Enviar** para mandar só os novos e os alterados, um por vez, com o progresso na tela (dá para cancelar no meio). Nada do projeto que não veio no envio é apagado. Com **Aplicar mudanças depois de enviar** ligado (o padrão), o projeto aplica as mudanças sozinho no fim (veja [Aplicar mudanças](#aplicar-mudanças)).

- Um arquivo só (como o `index.html` do site) abre uma confirmação curta: "index.html foi alterado" › **Enviar e aplicar**. Se ele for igual ao do projeto, o painel avisa "Nada mudou" e não envia nada.
- Arrastou a pasta do projeto inteira? Escolha **Só o conteúdo** para os arquivos de dentro dela irem direto para a pasta aberta, ou **Com a pasta** para ela entrar como uma pasta nova. O painel já sugere a opção certa: se o que tem dentro dela já existe no projeto, é o conteúdo.
- `node_modules`, `.git`, `__pycache__`, `venv`, `.venv`, `.DS_Store` e `Thumbs.db` são pulados sozinhos: as dependências a Cube instala a partir do `package.json`, do `requirements.txt` ou do manifesto da sua linguagem.
- **Até 500 MB por arquivo**, de qualquer tipo (um `.jar`, uma imagem, um banco SQLite). Na prática, o limite é o espaço do projeto: se ele acabar no meio, o envio para e diz o que foi e o que ficou.
- Se o envio parar no meio (sem internet, sem espaço), nada é aplicado e o painel diz quais arquivos foram e quais faltaram. Envie de novo: os que já foram aparecem como iguais.

<Tip>
  O .zip do **Novo projeto** e do **Enviar .zip** continua com o limite do plano (5 MB no Free e 10 MB nos pagos). Um arquivo maior, como um `.jar`, entra por aqui depois de o projeto existir.
</Tip>

## Buscar nos arquivos

No campo **Buscar texto nos arquivos**, digite o que procura e aperte Enter. A busca olha o projeto inteiro e mostra, por arquivo, cada linha em que o texto aparece. Clique numa linha para abrir o arquivo no editor com o cursor nela; o **Voltar** do editor devolve os resultados.

- O texto é procurado **exatamente como você digitou** (símbolos como `.*` ou `(` valem como texto), sem diferença entre maiúsculas e minúsculas, com até 200 caracteres numa linha só.
- Ficam de fora: `node_modules`, `.git`, `__pycache__`, `venv` e `.venv`, atalhos, arquivos que não são texto e os maiores que 1 MB.
- A busca mostra até **200 resultados** e para em 10 segundos. Se ela parar antes do fim, o painel avisa: busque um texto mais específico para achar o resto.

## Selecionar vários

Marque a caixa ao lado de cada arquivo ou pasta (ou a do cabeçalho, para marcar todos da pasta aberta; no celular, **Marcar todos** na barra). Com um ou mais marcados, a barra da seleção oferece:

- **Mover para…**: escolha a pasta de destino; cada item vai para lá com o mesmo nome.
- **Baixar .zip**: o painel monta um `.zip` só com os itens marcados (com o que está dentro das pastas) e o navegador baixa. O link vale 5 minutos e só para a sua conta. Até 500 MB e 20.000 arquivos; atalhos e as pastas das dependências ficam de fora. Um `.zip` por vez em cada conta: se outro ainda estiver baixando, espere ele terminar.
- **Excluir**: pede confirmação com a lista do que vai ser apagado. Não dá para desfazer.

São até 100 itens por vez, da mesma pasta. Se um item não der certo (um arquivo com o mesmo nome no destino, por exemplo), os outros seguem e o painel diz qual ficou e por quê. As pastas `node_modules` e `__pycache__` não entram na seleção.

## Reinstalar dependências

Quando uma dependência ficou quebrada ou pela metade, use **Reinstalar dependências**, ao lado de **Aplicar mudanças**. Ele apaga a pasta `node_modules` (no Python, o ambiente das dependências; no Go, os módulos baixados) e instala tudo de novo a partir do `package.json`, do `requirements.txt` (ou do `pyproject.toml`) ou do `go.mod`, **mesmo que eles não tenham mudado**. As edições ainda não aplicadas vão junto.

- O projeto sai do ar durante a instalação e volta sozinho no fim, se estava no ar.
- Acompanhe em **Logs** › **Instalação**: a primeira linha é "Reinstalando as dependências do zero".
- O envio aparece no **Histórico de envios** como "Dependências reinstaladas".
- Não aparece no site estático nem no Java, que não instalam dependências.

## Aplicar mudanças

Editar um arquivo não reinicia nada sozinho. Quando terminar, clique em **Aplicar mudanças**:

1. Se o `package.json`, o `package-lock.json` ou o `requirements.txt` mudou, as dependências são instaladas de novo. Se não mudou, a instalação é pulada.
2. O build roda de novo, se o projeto tiver um.
3. Se o projeto estava no ar, ele volta com o código novo.

Os arquivos aplicados ficam guardados como uma [versão](/hosting/versions) ("Edições nos arquivos" em **Configurações** › **Deploy**), para baixar ou voltar para eles depois.

<Tip>
  Mudou só um `.js` ou `.py`? **Reiniciar** também serve: o processo novo já lê os arquivos editados.
</Tip>

## Atualizar o código com um novo .zip

Em **Configurações** › **Deploy**, use **Enviar .zip** para trocar o código inteiro do projeto. Vale em **todos os planos**, inclusive no Free. Pela API, é o [Enviar novo código](/api-reference/projects/upload-code).

- A configuração do projeto (tipo, linguagem, comando e memória) **continua a mesma**. Um `cube.json` diferente no `.zip` novo é ignorado.
- As dependências só são instaladas de novo se o manifesto mudou.
- Se o `.zip` for recusado, os arquivos de antes ficam como estavam.

<Warning>
  O `.zip` novo **substitui a pasta inteira** do projeto (só as dependências instaladas ficam). Arquivos que o seu app criou, como um banco SQLite ou uploads, somem se não estiverem no `.zip`. Faça um [backup](/hosting/backups) antes de enviar (ele guarda esses arquivos e dá para voltar atrás), baixe pelo explorador, ou use **Aplicar mudanças** para trocar só o que editou.
</Warning>

O **Histórico de envios**, na mesma seção, mostra os 20 últimos envios, edições aplicadas e trocas de versão, com o resultado de cada instalação.

## Onde o seu app pode gravar

O seu código pode criar e gravar arquivos **dentro da pasta do projeto** (um banco SQLite, um JSON de configuração, uploads). Eles ficam guardados entre reinícios, mas um [novo .zip](#atualizar-o-código-com-um-novo-zip) substitui a pasta. Fora dela, só `/tmp`, que é pequeno e apagado quando o projeto reinicia.

Cada projeto tem um espaço em disco próprio. Veja quanto está usando em [Uso](https://app.cubehosting.com.br/usage). Se o espaço acabar, novas gravações falham: apague o que o projeto não usa.

## Excluir o projeto

Em **Configurações** › **Geral**, no fim da página, em **Zona de perigo**. O projeto para, os arquivos são apagados e o endereço do site deixa de funcionar. Não dá para desfazer, mas os [backups](/hosting/backups) ficam na página Backups por até 30 dias, para baixar ou [restaurar como um projeto novo](/hosting/backups#restaurar-como-novo).
