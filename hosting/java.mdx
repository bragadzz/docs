Um projeto Java roda um **.jar pronto**, com o `Main-Class` no manifesto e as dependências dentro (o "fat JAR"). A Cube não compila Maven nem Gradle: você gera o `.jar` no seu computador (ou no CI) e envia. Kotlin, Scala, Clojure e Groovy funcionam do mesmo jeito, desde que virem um `.jar` assim.

## Gerar o .jar

<Tabs>
  <Tab title="Gradle">
    Com o plugin Shadow, o `.jar` sai em `build/libs/` com tudo dentro.

    ```kotlin build.gradle.kts
    plugins {
        java
        application
        id("com.gradleup.shadow") version "9.2.2"
    }

    application {
        mainClass.set("bot.Main")
    }
    ```

    ```bash
    ./gradlew shadowJar
    ```
  </Tab>
  <Tab title="Maven">
    Com o `maven-shade-plugin`, o `.jar` sai em `target/` com tudo dentro.

    ```xml pom.xml
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-shade-plugin</artifactId>
      <version>3.6.0</version>
      <executions>
        <execution>
          <phase>package</phase>
          <goals><goal>shade</goal></goals>
          <configuration>
            <transformers>
              <transformer implementation="org.apache.maven.plugins.shade.resource.ManifestResourceTransformer">
                <mainClass>bot.Main</mainClass>
              </transformer>
            </transformers>
          </configuration>
        </execution>
      </executions>
    </plugin>
    ```

    ```bash
    mvn package
    ```
  </Tab>
</Tabs>

Confira no seu computador antes de enviar: `java -jar build/libs/bot-all.jar` precisa subir sem mais nada.

## Enviar

Ponha o `.jar` num .zip, junto dos arquivos que ele lê (como um `application.yml` ou a pasta `config/`). Um **único `.jar` na raiz** sobe sem `cube.json`: a Cube entende que é Java e roda `java -jar <arquivo>`. Com mais de um, ou para escolher a versão e a memória, use o `cube.json`:

```json cube.json
{
  "name": "Bot em Java",
  "language": "java",
  "version": "21",
  "command": "java -jar bot.jar"
}
```

No painel, o **Novo projeto** acha o `.jar` da raiz (e o de `target/` ou `build/libs/`) e já mostra o comando.

### .jar maior que o .zip do plano

O .zip vai até **10 MB** nos planos pagos, e o `.jar` já vem compactado: pôr no .zip não diminui nada. Um bot com o JDA, por exemplo, passa disso. Para esse `.jar`:

<Steps>
  <Step title="Crie o projeto sem o .jar">
    Envie um .zip só com o `cube.json` (e os arquivos pequenos que o `.jar` lê), com o `command` apontando para o `.jar`, como `java -jar bot.jar`. Deixe **Iniciar assim que terminar** desligado.
  </Step>
  <Step title="Arraste o .jar na aba Arquivos">
    Na aba **Arquivos** do projeto, arraste o `.jar` do seu computador para a lista (ou use **Enviar** › **Enviar arquivos**). O `.jar` não tem limite próprio: vale o de qualquer arquivo, **500 MB**, e o espaço do projeto. Veja [Arrastar arquivos e pastas do computador](/hosting/files#arrastar-arquivos-e-pastas-do-computador).
  </Step>
  <Step title="Inicie">
    Clique em **Iniciar**. Para trocar o `.jar` depois, arraste o novo na aba Arquivos: o painel mostra que ele foi alterado, envia e aplica as mudanças, e o projeto volta com o `.jar` novo.
  </Step>
</Steps>

No painel, o **Novo projeto** avisa quando o .zip passa do limite por causa de um `.jar`.

<Tip>
  Para o **Lavalink**, você não precisa enviar o `.jar`: o template [Lavalink](/hosting/lavalink) cria o projeto com um clique, e a Cube baixa o `Lavalink.jar` oficial e confere o SHA-256 antes de usar.
</Tip>

## Versões e memória

- **JDK 21** (a padrão) e **JDK 25**, as versões LTS. Um `.jar` compilado para o Java 17 ou 18 roda nas duas.
- **Mínimo de 256 MB** de memória, em qualquer plano: a máquina virtual do Java não sobe com menos. Por isso Java não cabe no Free (100 MB); o envio responde `language_not_in_plan`.
- **Sem `memoryMb`, o projeto entra com 512 MB** (ou com o que sobra no plano, nunca menos de 256 MB): um bot de verdade, com o JDA ou com áudio, passa dos 256 MB. O painel já começa em 512 MB.
- A Cube põe um teto na JVM pela memória do projeto (`JAVA_TOOL_OPTIONS`): o heap fica em até **60%** dela abaixo de 1 GB (**75%** de 1 GB para cima) e a memória direta, a dos buffers de rede e de áudio, em até **1/8**. O resto sobra para o próprio Java (classes, código compilado, threads). Passou do heap ou da memória direta, o log mostra um `OutOfMemoryError`. A linha `Picked up JAVA_TOOL_OPTIONS` no começo do log é o Java avisando disso.
- Para mudar, ponha um `-Xmx` no comando (`java -Xmx300m -jar bot.jar`), que vale por cima, ou defina a variável `JAVA_TOOL_OPTIONS` você mesmo em [Variáveis de ambiente](/hosting/environment-variables).

## Site ou API em Java

Um site Java escuta em `0.0.0.0` na porta da variável `PORT` (8080 por padrão), como qualquer [site ou API](/hosting/sites-and-apis). No Spring Boot: `server.port=${PORT:8080}` no `application.properties`.

## Problemas comuns

- **`no main manifest attribute, in bot.jar`**: o `.jar` não diz qual classe iniciar. Gere pelo Shadow ou pelo `maven-shade-plugin` com a `mainClass`, como acima.
- **`NoClassDefFoundError`** logo ao subir: faltam as dependências dentro do `.jar`. Use o `.jar` "all" ou "shaded", não o comum.
- **`UnsupportedClassVersionError`**: o `.jar` foi compilado para um Java mais novo que o do projeto. Escolha **Mais recente** (o Java 25) na versão, em **Configurações** › **Geral**.
- **`OutOfMemoryError: Java heap space`** ou **`Cannot reserve … direct buffer memory`**: o projeto precisa de mais memória. Aumente em **Configurações** › **Geral** e reinicie.
- **O .zip passou do limite do plano**: é o `.jar`. Siga [.jar maior que o .zip do plano](#jar-maior-que-o-zip-do-plano).
